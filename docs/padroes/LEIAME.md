# Padrões de engenharia

Como o time trabalha neste repositório. Cada guia é curto e prático: a regra, o motivo e o exemplo. As decisões de arquitetura por trás deles estão em [`docs/adr/`](../adr/) e resumidas no [`DECISOES.md`](../../DECISOES.md).

| Guia | Para quando |
|---|---|
| [Fluxo Git](fluxo-git.md) | Abrir uma sprint, commitar, abrir PR, fazer o merge e criar a tag |
| [Convenções de código](convencoes-de-codigo.md) | Escrever código no backend (C#), no frontend (TypeScript), em SQL e com IA |
| [Guia de testes](guia-de-testes.md) | Decidir que teste escrever, como nomear, como rodar e como não deixar o teste mentir |
| [Checklist de revisão](checklist-de-revisao.md) | Revisar um PR (ou o próprio código antes de abrir um) |
| [Fluxo de ADR](fluxo-de-adr.md) | Tomar uma decisão que muda a arquitetura, ou contrariar uma já tomada |

Os assistentes de IA (Claude Code) seguem as mesmas regras, resumidas para eles no [`CLAUDE.md`](../../CLAUDE.md).
